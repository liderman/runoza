This prerelease improves the coding agent and adds a persistent work UI: versioned
plans, saved change review and revision references, a server-side queue of follow-up
requests, context estimates, model-attempt history, and extension discovery.

Coding changes include bounded context/result handling, structured verification,
managed file revisions, repeated-action protection, and token-budget accounting.
Optional pilots add bounded parallel reads, model recovery from saved tool-result
boundaries, read-only research, and managed-file rollback preview/application.

Rollback requires a fresh preview and separate confirmation of the exact file set.
The worker rechecks versions and records each outcome. Conflicts prevent unsafe
writes; partial or unknown outcomes are retained without automatic replay. This is
not a general Git reset or a rollback of shell commands, created/deleted files, or
all external side effects.

Migrations 038–045 preserve existing users, conversations and files while adding
coding revisions, plans, queue records, model/research metadata and rollback journals.
Back up PostgreSQL, object storage, terminal workspaces, compose.yaml and .env before
upgrading. Keep the existing .env, encryption keys and Compose project name. Replace
compose.yaml with this release asset and update any RUNOZA_IMAGE override, then run
docker compose pull and docker compose up -d --wait --wait-timeout 180.

RUNOZA_READ_BATCH, RUNOZA_MODEL_JOURNAL, RUNOZA_RESEARCH, RUNOZA_ROLLBACK_PREVIEW and
RUNOZA_ROLLBACK_APPLY remain disabled by default. Research requires model journaling;
rollback application requires preview. Disabling rollback does not reverse files
already restored. Do not downgrade the application against an incompatible schema.

Local validation: npm run check passed with 124 unit tests and 226 UI tests; the
preceding backend integration run passed 306 tests with 6 infrastructure skips.
Chrome and native macOS x64 Electron smoke covered plans, queues, change review,
rollback confirmation/conflicts/partial outcomes, languages, themes and narrow
layouts. Two UI defects found during that run were fixed. File rollback used a
test executor; real OS rollback and the skipped infrastructure scenarios are not
claimed as validated by that smoke. Tagged CI reruns the release checks.

Desktop archives remain preview builds without production signing, macOS
notarization or automatic updates. See docs/research/zcode-implementation-plan.md
and docs/research/zcode-browser-desktop-ui-results.md for scope and limitations.

System administrators can now allow local HTTP and internal HTTPS MCP servers from
**Administration → MCP**, without editing `.env` or restarting the application. Enter
one origin per line, such as `http://192.168.1.100:9584`, without the MCP path or token.
Keep the complete secret URL in the MCP connection itself.

Settings are stored per organization and apply to connection creation and editing,
tool discovery, tool calls, and OAuth. Removing an origin blocks subsequent requests,
including those in reused MCP sessions. Existing `MCP_ALLOWED_INTERNAL_ORIGINS` entries
remain additive and appear read-only. A blocked MCP URL now produces an actionable
message pointing to the administration screen.

Upgrading from alpha.7 applies migration `035_mcp_network`. Back up PostgreSQL, object
storage, terminal volumes and the existing `.env` before upgrading. Preserve encryption
keys and the Compose project name. Replace only `compose.yaml` with this release's asset,
then run `docker compose pull` and `docker compose up -d --wait --wait-timeout 180`.
Update or remove an existing `RUNOZA_IMAGE` override to use the new release image.
The migration service runs before the updated API and worker start. A rollback to an
older binary requires its matching database backup because schema versions are checked.

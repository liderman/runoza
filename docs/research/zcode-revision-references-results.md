# Runóza: обсуждение строк сохранённого diff

27 ноября 2026. Реализована следующая часть этапа 6 [общего плана](zcode-implementation-plan.md): выбор строк before/after и отправка точной ссылки в контекст агента. Это продолжение [read-only обзора](zcode-readonly-review-results.md). Изменения локальные, без commit/push/deploy.

## Поведение

В diff номера строк каждой стороны стали доступными кнопками. Нажатие выбирает одну строку, Shift расширяет диапазон на той же стороне; смена стороны начинает новый диапазон. Поля «С»/«По» и выбор стороны позволяют задать диапазон с клавиатуры. «Обсудить выделенное» проверяет фрагмент на сервере, добавляет ссылку в composer и возвращает фокус к существующему тексту без его замены. На широком экране workspace остаётся открытым. На узком экране возврат к composer закрывает панель через существующую защиту несохранённых файлов; обычный просмотр diff по-прежнему не закрывает workspace и не останавливает PTY.

Ссылка показывает path, сторону, строки, сокращённый hash и состояние применения. В деталях доступны полный SHA-256, run, беседа-источник и workspace. Ссылку можно убрать из черновика. До четырёх фрагментов на сообщение, каждый до 100 строк и 16 KiB UTF-8. Полный файл автоматически не прикладывается.

В API отправляются только `runId`, `changeId`, `side`, `hash`, `startLine`, `endLine`. Текст, path, workspace и состояние берутся на сервере. Ошибка источника оставляет текст и ссылки в черновике; отсутствующие версии не подменяются текущими файлами. После успешного ACK очищаются только отправленные ревизии текста и ссылок. Более новый черновик, в том числе с тем же текстом, сохраняется. Retry ответа, редактирование старого сообщения и compaction не потребляют ссылки несвязанного черновика.

У отправленного сообщения остаётся структурированная ссылка. Retry использует её сохранённый контекст; редактирование заново разрешает ссылку через сервер. Fork копирует идентичность источника и проверенный excerpt; исходная беседа и её права не копируются. При создании ветки из пользовательского сообщения ссылки возвращаются вместе с текстом черновика.

## Сервер и данные

Новая добавочная миграция — `039_revision_references`: JSONB `messages.revision_references` с ограничением на четыре записи. Старые migrations не менялись; старые сообщения получают пустой массив. У публичного `ChatMessage.revision_references` нет `excerpt`: API истории возвращает только метаданные.

`POST /api/v1/conversations/:id/revision-references/resolve` — предварительное read-only разрешение ссылки. Проверяется доступ к беседе назначения и отдельно к сохранённому источнику. Отправка run требует права записи в назначение; источник может принадлежать другой доступной беседе той же организации. Это позволяет сохранять ссылки в fork, не предоставляя доступ через сам факт копирования. Ответ предварительного разрешения — `private, no-store`; UI хранит в черновике только метаданные.

`POST /api/v1/conversations/:id/runs` принимает необязательный `revisionReferences`. При обычной отправке сервер повторно читает revision bundle, проверяет его SHA-256, формат, path, base64 и hash выбранной стороны, затем извлекает точный диапазон. Создание/удаление не позволяет выбрать отсутствующую сторону; пустой файл не содержит строки 1. BOM, CRLF, Unicode и отсутствие завершающего newline сохраняются. Бинарные/non-UTF-8 данные, несуществующий диапазон и превышение лимита отклоняются, без тихого усечения. Источник ограничен 256 KiB и 4 000 строками; чтение bundle — 3 MiB и 15 секундами.

Сервер сохраняет только проверенный ограниченный excerpt вместе с сообщением. Он участвует в расчёте context budget и передаётся модели как JSON с явной маркировкой исторических недоверенных данных, без дополнительных разрешений на исполнение. Prepared/unknown не превращаются в подтверждённую запись.

Перед исполнением queued run и перед последующими model rounds повторно проверяются источник, hash, ready revision и живой ACL; проверка включена и в heartbeat отмены. Недоступная ссылка текущего сообщения блокирует запуск. Недоступная старая ссылка заменяется явным marker без excerpt. Изменение материала контекста меняет source hash, поэтому старый compaction checkpoint с недоступным фрагментом не восстанавливается.

Lifecycle выбранного excerpt следует сообщению: он хранится в БД до удаления сообщения/беседы, отдельно от 30-дневной retention revision blob. После удаления/истечения revision автоматическая передача excerpt прекращается. Это не удаляет уже отправленные провайдеру данные или ранее сохранённые ответы ассистента.

## Выпуск и ограничения

Перед запуском новой версии выполнить миграции штатным runbook с восстановимым backup. Production schema в этой задаче не менялась. Downgrade до 038 удалит колонку со ссылками и excerpts: перед таким откатом нужен backup; сами тексты сообщений миграция не меняет. Новых зависимостей нет. Доступность target нового запуска проверяется по прежним правилам; чтение сохранённого source не требует подключения его устройства.

Это контекстные ссылки для обсуждения в обычном чате, не отдельная система inline-комментариев или review threads. Live Git, plan mode, очередь, rewind и субагенты не добавлены. Открытие сохранённой ссылки отдельным permalink и долговременное хранение draft после перезагрузки не входят в эту поставку.

Геометрия настоящего браузера и native Electron smoke, screen reader и contrast audit остаются `not_run`. Narrow CSS, сборки двух оболочек и component tests не заменяют эти проверки. Использован локальный [Gravity skill](../../.agents/skills/gravity-ui/SKILL.md); новые браузеры и screenshot tooling не устанавливались.

# Этап 9: история и каталог расширений

Изменения выполнены поверх этапов 0–8 в рабочем checkout. Общий frontend используется web и Electron. Новые зависимости и миграции не требуются; версия схемы остаётся 042. Пользовательская установка не обновлялась.

## Измеренная проблема и изменения

В `ChatWorkspace` каждый ввод символа и SSE event заново строили всю ветку, создавали объекты сообщений, действия и настройки Markdown. Поиск run и версий ответа выполнялся повторными `find`/`filter` внутри прохода по сообщениям. Из-за новых ссылок не работала уже имеющаяся мемоизация строк AIKit.

История выделена в `ChatHistory`. Индексы сообщений, runs и вариантов ответа строятся одним проходом. Ветка собирается через `push` и `reverse`, вместо повторного `unshift`. Проекции неизменившихся сообщений переиспользуются; cache ограничен текущей веткой и сбрасывается при смене беседы. Глобальные условия действий — ACL, занятость, наличие выбранной модели — остаются зависимостями пересчёта. Copy обновляет только затронутые сообщения. Обработчики действий вызывают функцию из последнего committed render, поэтому fork/retry используют актуальное состояние workspace.

Стабилизированы Markdown options, обработчики цитат и footer. Контекст инструментов индексирует runs; мемоизированное тело карточки не обновляется из-за изменения чужого run. DOM истории остаётся смонтированным: раскрытые блоки, выделенный текст, ссылки и текущая позиция чтения сохраняются. Исходные правила автоматической прокрутки и кнопка перехода к последним сообщениям сохранены.

Виртуализация не включена: выявленная повторная работа устраняется сохранением ссылок и индексами. Первичное создание большой истории по-прежнему линейно зависит от числа сообщений и карточек. Измерения jsdom не устанавливают приемлемость реальной браузерной задержки; решение о виртуализации требует отдельного профиля браузера и проверки выделения/доступности.

## Числа и воспроизводимость

Все замеры используют синтетические данные, Vitest/jsdom, без модельных запросов. Это показатели работы компонентов, а не FPS или задержка реального браузера. Время зависит от нагрузки машины; жёсткого порога в тестах нет.

Одинаковая fixture `coding-history-v1`: 1000 сообщений, длинный вывод в каждом сотом сообщении, обновление последнего ответа. Единственное изменение fixture после исходного замера — использование того же стабильного объекта Markdown options, что и в production-компоненте.

Это узкий контроль влияния стабильных props AIKit, не сравнение всего приложения до/после. Отдельный тест использует настоящий `ChatHistory` с кнопками действий, раскрытой tool card, reasoning и источниками: 1000 сообщений, 500 первоначальных проекций ответов, **1 проекция** при streaming update, **0** при вводе в composer. В отдельном прогоне первичный mount занял 5420 мс, update 71 мс; эти числа нельзя напрямую сравнивать с облегчённой AIKit fixture выше. Проверены сохранение DOM узла и selection, открытого disclosure, scroll anchor, фокуса, действие Stop и переход к источнику. Проверка Stop здесь подтверждает обработку события, не миллисекунды отклика браузера; серверную отмену покрывает существующая регрессия.

Диагностика находится в игнорируемом `work/zcode`: `stage9-ui-before.json`, `stage9-ui-after.json`, `stage9-history-final.json`. Полный UI-прогон обновляет также `ui-baseline.json` и `stage9-history.json`.

## Каталог, примеры и ссылки в черновике

В каталоге и picker различаются установка навыка/настройка подключения, включение и доступность в текущем контексте. Показываются реальные причины недоступности: запрет администратора, отключённое устройство, нужная рабочая область, исчезнувшая версия. Наличие MCP в каталоге не объявляется успешной авторизацией: интерфейс прямо сообщает, что она проверяется при подключении, а действия подчиняются текущим разрешениям.

Добавлены EN/RU примеры. В picker кнопка «Попробовать» повторно читает каталог текущей беседы, проверяет доступность и ручную вызываемость навыка, добавляет актуальную version/connection reference и дописывает пример к имеющемуся черновику. Ничего не отправляется и не исполняется. Пустой черновик заполняется примером, непустой сохраняется; фокус возвращается в composer. MCP reference можно удалить отдельной кнопкой. Отмена диалога, смена scope, workspace или прав инвалидируют незавершённый выбор.

Не добавлен новый cache схем/инструкций и не изменены серверные ACL. Существующий React Query cache остаётся в authentication-scoped provider, ключи каталогов содержат conversation/project; pin инвалидирует extensions. Для принятия примера выполняется свежая проверка. Имеющаяся регрессия совместных status/history consumers проверяет один первоначальный activity request. Измерений, оправдывающих новый schema cache или другой протокол deferred tools, нет; эти изменения не включены.

## Расширения конкретного запуска

Snapshot беседы теперь содержит необязательное поле `runs[].extensions`, построенное из сохранённого `extension_manifest`. Сервер возвращает только имена, ID и версии навыков, признак предварительной загрузки инструкций, имена/ID MCP и количество предварительно загруженных схем. Endpoint, command, envRefs, schemas и credentials не возвращаются в этом поле. Сам manifest в ответ не попадает.

UI показывает «Расширения на старте запуска», отдельно поясняя отличие доступности от фактического вызова. On-demand расширения не выдаются за выполненные. Фактические вызовы остаются в журнале действий. Изменение имени/отключение подключения в текущем каталоге не меняет сохранённый список. Старые runs без manifest используют сохранённые skill versions и MCP IDs с явной пометкой, что имя не записано. Новых запросов к текущему каталогу ради истории нет.

# Этап 11: восстановление от модельной границы

Дата: 27 ноября 2026. Изменения находятся в текущем checkout; публикация и включение на рабочем сервере не выполнялись.

## Поведение

`RUNOZA_MODEL_JOURNAL=true` включает журнал для новых agent runs. Значение сохраняется в `coding_config`: смена переменной окружения не меняет уже созданный run. По умолчанию флаг выключен. Plain chat сохраняет существующий механизм восстановления текста; `read_batch` включается отдельным флагом.

Перед запросом сохраняются точный подготовленный контекст, инструкции, версия конфигурации, fingerprint prompt/модели/схем инструментов и целевой контекст. Завершённое сообщение assistant с tool calls сохраняется до первого выполнения инструмента. Каждый внешний call получает durable intent, а затем канонический tool result. Связи с `code_actions` сохраняют доказательства исполнения, включая дочерние чтения `read_batch`. Сохраняется известная статистика cacheRead/cacheWrite; неизвестный расход не оценивается выдуманными значениями. Попытки генерации и их usage связаны с модельным раундом через `generation_attempts.model_round_id`.

Граница подтверждается только после полного batch и отсутствия незавершённых или неизвестных действий. Проверяются порядок, имена и идентификаторы call/result во всём контексте. Восстановление использует публичные `Agent.state.messages` и `Agent.continue()` установленного Pi, без форка и исправлений зависимостей.

При допустимом сбое провайдера или истечении heartbeat worker переводит run в очередь под блокировкой строки, сбрасывает lease и сохраняет новый ID задания pg-boss. Новый worker повторно проверяет текущие права, fingerprint и ledger. Старые callbacks, журнал, usage и cleanup не могут продвинуть run с новым lease. На подтверждённой границе workspace сохраняется; при takeover отзывается старый environment fence, чтобы новый worker мог получить среду без потери файлов. Поздний release старого lease не закрывает новую среду. Повторный worker завершает уже сохранённый финальный ответ без обращения к модели.

## Границы автоматического продолжения

- Восстанавливается целиком сохранённый tool batch либо подготовленный следующий запрос после подтверждённого batch, в том числе после compaction.
- Вызовы с отсутствующим результатом не запускаются повторно, даже если их `code_actions` показывает успех. Журнал исполнения не подменяет точный канонический ответ инструмента.
- Неполный batch, неизвестный исход, частично показанный новый ответ и изменённая конфигурация останавливают автоматическое продолжение. Доказательства остаются в истории для проверки.
- Отмена не ставит run на повтор. При отзыве доступа новый worker останавливается до обращения к модели и инструментам. Сохранённый текст не стирается при отказе проверки доступа.
- Не более двух восстановлений модельной границы. Существующие лимиты попыток генерации, времени и инструментов сохраняются между worker; сжатие их не обнуляет.
- Один сохраняемый JSON ограничен 4 МиБ; размер batch — 256 calls. Старые раунды сохраняют assistant/results, а полный request context хранится только для новейшего раунда.

Механизм не обещает exactly-once для произвольной внешней системы: при разрыве между эффектом и сохранением результата он прекращает выполнение. Проверка внешнего состояния требует отдельного разрешённого действия или решения пользователя.

## Данные и интерфейс

Миграция `043_model_journal` добавляет `model_rounds`, `model_tool_calls`, метаданные восстановления в `chat_runs` и связь с попытками генерации. Есть обратная миграция; откат удаляет новый журнал, сохраняя обычные runs, сообщения и `code_actions`. Перед откатом нужно остановить worker; старый бинарник использовать только с соответствующей версией схемы.

Snapshot и SSE содержат только номер раунда, количество восстановлений, состояние и код причины. Внутренние сообщения модели, конфигурация журнала и dispatch ID не включаются в snapshot. Действует существующий ACL беседы.

Общий web/Electron компонент показывает границу восстановления, подтверждение результатов и причины остановки на EN/RU. Он не добавляет кнопку слепого повтора инструмента. Старые runs без журнала не получают пустой блок.

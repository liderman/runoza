# Этап 12b: предпросмотр отката управляемых файлов

Дата: 27 ноября 2026. Реализована запрошенная первая часть 12b — предпросмотр. Изменения находятся в текущем checkout; публикация и включение на рабочем сервере не выполнялись.

## Пользовательский сценарий

При `RUNOZA_ROLLBACK_PREVIEW=true` в общем диалоге «Изменения запуска» появляется кнопка предпросмотра всего запуска. Она доступна после завершения запуска пользователю с действующими правами работы с workspace. Флаг выключен по умолчанию и независим от исследователя 12a. Старые журналы и просмотр сохранённых diff продолжают работать при выключенном флаге, недоступной среде и у пользователей, имеющих только права просмотра.

Открытие обычного журнала не читает текущие файлы. Отдельный запрос предпросмотра проверяет сохранённые версии и текущее содержимое. Для каждого пути показываются исход:

- **Можно вернуть на момент проверки:** текущие байты совпадают с последней подтверждённой версией управляемой записи.
- **Конфликт:** текущий файл отличается; пользовательские или последующие изменения не предлагается затереть.
- **Не поддерживается:** невозможно подтвердить допустимую операцию, целевую папку, целостность версий или безопасно прочитать текущий файл.

Рядом показаны before/after/current hashes, причина и переходы к первой и последней сохранённым записям. Они открывают существующий review версий до и после. Интерфейс сообщает время проверки и явно отделяет совпадение в этот момент от будущего применения. При любой неподдерживаемой записи или конфликте весь набор не получает общий статус готовности. Пустой журнал также не считается готовым откатом.

## Поддерживаемые изменения

Пилот проверяет только замену существующих текстовых файлов UTF-8, включая пустые файлы, BOM и CRLF. Допустимы подтверждённые управляемые записи `write_file`, `edit_file`, `files_export`, `skills_copy`, имеющие обе сохранённые версии. Для нескольких изменений одного пути нужна непрерывная цепочка `after_hash → before_hash` с однозначным порядком. Для предпросмотра возврата всего запуска используется версия до первой записи и после последней.

Создание и удаление файлов, бинарное содержимое, неизвестные/незавершённые исходы, shell-наблюдения, неоднозначный порядок, разрыв цепочки, недоступные или повреждённые revisions и другой target показываются как неподдерживаемые. Они не превращаются в готовность по одному совпавшему hash. У неподдерживаемой записи текущий путь не читается. Данные shell-наблюдений остаются частичными: журнал не обещает перечислить все побочные эффекты.

## Реализация и ограничения

API ставит `rollback.preview` в существующий `workspace_requests` с request ID, actor, исходным run, поколением среды и desktop target. Идентификатор запроса идемпотентен в пределах той же цели. Нет новой таблицы, миграции, задания агента, модельного вызова или новой беседы.

Workspace worker использует только `inspectWorkspace` и bounded `readFile`. Он не вызывает acquire/provision, команды, writers или восстановление среды. Если рабочая папка закрыта либо устройство offline, запрос возвращает существующую ошибку; сохранённый review остаётся доступен. Server и desktop проходят одинаковую проверку идентичности цели и прав через существующие adapters. Текущий hash вычисляется сервером по полученным байтам, а не принимается из поля digest исполнителя.

Сохранённые bundles читаются через storage service; проверяются hash самого bundle, path и hashes обеих версий. В ответе нет ключей S3, полного текущего содержимого, внутренних аргументов задания и fingerprint журнала. Live ACL проверяется до чтений, между ними и перед публикацией. Новый активный run, изменение target/generation, отключение функции или отзыв доступа останавливают проверку. Retention и состав журнала перепроверяются после чтения и при выдаче результата.

Лимиты: до 50 записей журнала, 25 различных путей, 8 MiB суммарно прочитанных bundles и текущих файлов, 30 секунд выполнения. Задание старше двух минут не исполняется. Готовый результат доступен 60 секунд; затем нужна новая проверка. Это последовательные наблюдения файлов, не атомарный снимок рабочей папки и не блокировка внешних редакторов. Истечение срока, смена поколения среды или недоступность доказательств скрывают старый результат вместо сохранения зелёного статуса.

Отмена относится только к предпросмотру и не вызывает родительский Stop. Worker отслеживает отмену и доступ, прерывает in-flight чтение через AbortSignal и не сохраняет поздний результат отменённого задания. Закрытие диалога отменяет незавершённую проверку; учтён случай закрытия до позднего ответа enqueue. Перезапуск worker не повторяет незавершённую проверку автоматически. Общий endpoint workspace actions не выдаёт preview result в обход специальных проверок срока и сохранённых версий.

## Что не входит в эту поставку

API и кнопки применения отката отсутствуют. Предпросмотр не изменяет файлы, историю чата, Git, shell-эффекты, approvals или состояние родительского запуска. Отключение флага запрещает новые проверки и останавливает ожидающие/выполняющиеся; новый preview можно запросить после включения. Откат схемы не требуется, её версия остаётся `044_readonly_research`.

Следующая часть 12b — отдельное применение поддерживаемых изменений: повторно проверить весь набор до первой записи, привязать решение к точным версиям и target, использовать существующие проверки permissions и conflicts, сохранить журнал прогресса и честный исход частичного сбоя. Успешный предпросмотр не является разрешением и не может использоваться как долгоживущий apply token.
